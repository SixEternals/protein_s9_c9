标注一致性：

- `observed_positive` 中 read>0 的样本为 38,912 行，read 缺失 407 行，没有 read=0。

- 因此标签本身是二值且基本自洽，但 `label=0` 仍然只能解释为 `unobserved_candidate`，不能解释成实验验证安全。

修正旧认知：

- 早期文档说 CSV 只有 5 个字段，这是错的。真实 CSV 有 11 个字段：`sgRNA_seq`, `off_seq`, `read`, `sgRNA_type`, `label`, `chr`, `Location`, `Direction`, `Length`, `Method`, `id`。
- 早期文档说约 950 万样本、418 条 sgRNA，也与本次下载文件不一致。当前 Figshare v2 CSV 是 6,393,373 行，`sgRNA_type_unique=282`。
- `Method` 字段存在，但约 328 万行为空，所以 Tier-aware 训练只能对 Method 明确且已确认含义的子集使用；未知方法或空 Method 必须作为 `unknown` 处理。

|:---|:---|
| `rna-fm` package | 0.2.2 |
| API | `fm.pretrained.rna_fm_t12` |
| legacy API `esm1b_rna_t12` | 当前包中不存在 |

| embedding dim | 640 |
| 参数量 | 99,521,546 |
| smoke forward | 通过 |

结论：RNA-FM 本体是满血版，不是缩水版。PyTorch 2.6+ 默认 `weights_only=True` 会拒绝 checkpoint 中的 `argparse.Namespace`，脚本已通过窄范围 safe global 兼容官方 RNA-FM 权重。

CCLMoff Figshare checkpoint：

- `data/cclmoff/CCLMoff_V1.ckpt`
- MD5：`80b311715969524a3972ab75928f3969`
- 审计报告：`results/audits/cclmoff_checkpoint_audit.md`

重要风险：

该文件确实与 Figshare API 元数据一致，也能用 `torch.load(..., weights_only=False)` 加载；但其 `state_dict` 是 `encoder`/`decoder` 风格，包含 286 个 key、47,369,757 个 tensor 参数，缺少公开 `CCLMoff/my_model.py` 里的 `rna_model`、`dense1`、`dense2` 权重键。因此它不能直接当作公开 CCLMoff RNA-FM + MLP 推理权重使用。

后续如果要严格复现 CCLMoff，需要解决这个权重/代码不匹配问题：要么找到官方匹配的 `CCLMoff_V1.pt` 或 inference 代码，要么自己用公开 CSV 重新训练 RNA-FM + MLP 头。

## 四、P0/BL0 加权平均 baseline

当前 P0 定义：不训练新神经网络，只把两个已有模块的预测概率做加权平均。

公式：

```text
p_fused = w * p_R9_DeepFocus + (1 - w) * p_C9_ConMismatch9
```

配置：

- `configs/bl0_weighted_average.yaml`
- 数据集：`/data/zwf/project/zhb/data/GUIDE-seq/GUIDE-seq_9bit.npz`
- 样本：全量 520,281 行
- observed_positive：1,123
- unobserved_candidate：519,158
- 划分：train 364,197 / val 78,042 / test 78,042
- R9 checkpoint：`artifacts/full_upgrade_guide_seq_deepfocus/seed_43/full/deepfocus_r9_GUIDE_seq.pt`
- C9 checkpoint：`artifacts/full_upgrade_guide_seq_conmismatch9/seed_43/full/conmismatch9_c9_GUIDE_seq.pt`
- R9/C9 feature cache：均已抽样校验前 64 行，顺序和编码内容一致

验证集搜索：

- 搜索范围：`weight_region_r9 = 0.00 ... 1.00`，步长 0.01
- 最优权重：`weight_region_r9=0.16`，`weight_run_c9=0.84`

测试集结果：

| 模型 | AUROC | AUPRC | Accuracy | Precision | Recall | F1 |
|:---|---:|---:|---:|---:|---:|---:|
| R9/DeepFocus only | 0.997845 | 0.827919 | 0.990531 | 0.180493 | 0.952663 | 0.303487 |
| C9/ConMismatch9 only | 0.998469 | 0.848579 | 0.995426 | 0.312749 | 0.928994 | 0.467958 |
| Weighted average | 0.998795 | 0.850950 | 0.995361 | 0.309665 | 0.928994 | 0.464497 |

结论：

- 加权平均相对 C9 单模型 AUPRC 从 0.848579 提升到 0.850950，提升约 0.00237。
- 提升幅度不大，但方向正确，说明两个旧模块存在少量互补信息。
- 最优权重高度偏向 C9（84%），说明在 GUIDE-seq seed_43 这组设置下，连续错配模块比区域模块贡献更大。
- P0 已记录到 `results/experiments.csv`，状态为 `completed`。

## 六、下一步建议

1. 先不要给严格 CCLMoff 复现打 `BL0-v1.0` tag，因为 Figshare `CCLMoff_V1.ckpt` 与公开代码头不匹配。
2. 可以给当前加权平均 baseline 单独命名为 `BL0-P0-weighted-average` 或 `P0-weighted-v1.0`，等你确认后再打 tag。
3. 后续 BL3/BL4/BL5/BL6 不应直接复用 CCLMoff Figshare checkpoint；RNA-FM 本体权重可以用，CCLMoff 头部权重目前不能用。
4. Tier-aware 训练要基于 Method 非空且方法已确认的样本子集，或者先建立 `Method/sgRNA_type -> Tier` 映射表。
