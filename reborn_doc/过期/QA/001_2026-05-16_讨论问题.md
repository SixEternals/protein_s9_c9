## 2. 融合模型先做到哪一层？

从保守到激进大概有四级：

1. 简单加权融合：两个旧模型各自输出分数，然后固定权重平均。
2. Stacking：两个旧模型输出分数，再接一个小模型学习怎么融合。
3. 多视角端到端融合：区域编码分支 + 连续错配分支，在模型内部做 Cross-Attention 和 Gated Fusion。
4. RNA-FM + 先验特征融合：在 CCLMoff/RNA-FM 预训练底座上再加入 seed 区和连续错配先验。

我的建议是不要一上来直接冲第 4 级。更稳的路线是：

`简单加权 baseline -> stacking baseline -> 多视角融合主模型 -> 再考虑 RNA-FM 增强版`

但最终要看这次作业时间和你希望做到什么程度。

## 3. seed 区和连续错配到底怎么结合？

我理解这里有一个核心疑问：

> 连续错配检测是不是应该只在 seed 区里面做？

我的初步判断是：不应该只在 seed 区做。

更合理的是全序列都做连续错配检测，但模型需要知道连续错配发生在哪里。也就是说：

- 普通区连续错配：有影响，但可能不是最高危。
- seed 区连续错配：高危，需要重点建模。
- PAM 附近连续错配：也可能非常关键，不能直接忽略。

所以更好的设计不是“只在 seed 里找连续错配”，而是让模型同时看到：

- 这个位置属于 normal / seed / PAM 哪个区域
- 这个位置是否处在连续错配片段中
- 连续错配片段长度是 1、2、还是 3+

这样模型可以自己学出“seed 区连续 3 个错配特别危险”这类组合规律。

# R

## 1. 多视角端到端融合 vs RNA-FM + 先验特征融合

这两个方向不是一回事。

### 多视角端到端融合

这个方向的重点是“怎么把你们已经有的两套特征真正融合起来”。

它通常意味着：

- 输入还是你们现有的两种先验表示
  - 区域视角：PAM / seed / normal
  - 连续错配视角：单点错配 / 连续2个 / 连续3+
- 模型内部有两个分支
- 分支之间通过 Cross-Attention 交互
- 最后再用 Gated Fusion 做样本级动态融合

它的本质是：

> 先把你们已经验证过的知识编码吃透，再让模型自己决定不同样本该听哪个分支更多。

这个方案的优点是改动相对局部，和现有代码、现有数据最容易衔接，适合作为主线创新。

### RNA-FM + 先验特征融合

这个方向的重点不是“两个已有模块怎么融合”，而是“把整个底座换成预训练语言模型，再把先验特征接进去”。

它通常意味着：

- 先用 RNA-FM 这类预训练模型做序列表征
- 输入形式更接近原始序列或伪 RNA 序列
- 再把区域信息、连续错配信息，甚至其他先验信息，作为额外特征注入

它的本质是：

> 先让大模型学序列语言，再告诉它哪些区域和哪些错配模式更重要。

### 为什么后者更激进

因为后者不只是改“融合方式”，而是改了更底层的三件事：

1. **表示方式变了**  
   你不再只是用现成的区域编码和连续错配编码，而是要和预训练底座的输入形式对齐。

2. **参数和训练范式变了**  
   预训练底座的调参、冻结、微调策略，都比你们现在的轻量模型复杂。

3. **算力和数据需求更高**  
   预训练模型通常更吃资源，训练和调参成本也更高。

所以如果从“科研推进顺序”来看，合理顺序是：

1. 先做简单加权 baseline
2. 再做 stacking baseline
3. 再做多视角端到端融合
4. 最后再考虑 RNA-FM 增强版

这就是为什么我说 RNA-FM + 先验特征融合更激进。

## 2. Leave-One-sgRNA-Out 和 Leave-One-Dataset-Out 的区别

这两个验证方式都在测“泛化能力”，但测的是不同层级的泛化。

### Leave-One-sgRNA-Out

做法是：

- 每次留出一条 sgRNA 的全部样本做测试
- 训练时完全不见这条 sgRNA

它测的是：

> 模型能不能对“没见过的 sgRNA”仍然给出靠谱预测。

这个验证关注的是**guide 层面的泛化**。  
训练集和测试集通常仍然来自同一批数据源、同一类实验平台、同一分布，只是 sgRNA 身份不同。

### Leave-One-Dataset-Out

做法是：

- 每次留出一个完整数据集或一个研究来源作为测试集
- 训练时完全不使用这个数据集

它测的是：

> 模型能不能跨实验平台、跨研究、跨数据分布也保持稳定。

这个验证关注的是**域迁移 / 数据集层面的泛化**。  
它比 Leave-One-sgRNA-Out 更难，因为测试集不仅是新 sgRNA，还是新分布。

### 两者强度对比

一般来说：

`Leave-One-Dataset-Out` 比 `Leave-One-sgRNA-Out` 更严格，也更难。

原因很简单：

- LOSO 主要是在同一数据分布里换一个没见过的 sgRNA
- LODO 是连数据来源、实验条件、噪声模式都可能一起变

所以如果你说“我们是做科研的”，那我同意以 `Leave-One-sgRNA-Out` 作为主验证方法。  
它已经比普通随机切分更有说服力，而且更贴合“模型是否学到了通用规律”这个问题。

如果后面时间够，再补一组 `Leave-One-Dataset-Out`，那会更强，但工作量也更大。
