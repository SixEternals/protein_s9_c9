## 一、项目现状与目标

### 已完成
- 独立的两套检测系统：seed 区脱靶风险评分 + 连续交错（ConMismatch）脱靶检测
- 对应模型：R9/DeepFocus（seed 区）、C9/ConMismatch9（连续错配）

### 下一步目标
构建**三视角融合模型**，统一整合：
1. **Region 编码**（9-bit，碱基类型 + 错配方向 + 区域标记）
2. **全局 Run 编码**（9-bit，碱基类型 + 错配方向 + 连续错配状态）+ Seed 梯度加权
3. **RNA-FM 预训练编码**（640 维，来自佛山大学 CCLMoff 的预训练模型）

通过与 BL0（CCLMoff 复现）、BL3-hard、BL4、BL5 系列、BL6 的递进式对比，验证先验特征与融合策略的价值。

## 二、核心概念定义

### 坐标约定（硬性约束，不可违背）
- **position 1–20**: protospacer / guide-target aligned region
- **position 1**: PAM-distal end（最远端）
- **position 20**: PAM-proximal end（紧挨 PAM）
- **positions 21–23**: PAM region（NGG）
- **hard seed**: positions 16–20（工程约定，非生物学真理）

> ⚠️ 风险：如果坐标方向反了，Region 编码的 seed/ordinary 标记全错。任何涉及位置索引的代码修改前，必须对照此约定。

### 术语规范
- 不用 `"negative"`，用 `"unobserved_candidate"`
- `label=0` ≠ 安全位点，只是没被实验检测到
- `"positive"` 可用（表示实验检测到切割）

### 检测方法 Tier 分层（用于 Loss Weighting）
| Tier | 检测方法 | 权重 | 说明 |
|:---:|:---|:---:|:---|
| Tier 1 | DISCOVER-seq, DISCOVER-seq+, GUIDE-seq, HTGTS | 1.0 | 直接检测体内真实切割，假阳性率低 |
| Tier 2 | IDLV, BLESS, BLISS, PEM-seq, VIVO | 0.7 | 间接标记，可能漏检，中等可信度 |
| Tier 3 | CIRCLE-seq, CHANGE-seq, Digenome-seq, SITE-seq | 0.4 | 体外条件≠体内，CIRCLE-seq 假阳性率~88% |

### CCLMoff 数据集真实审计结论（必须在后续文档中继承）

已下载并校验 Figshare v2 文件 `data/cclmoff/09212024_CCLMoff_dataset.csv`：

- 文件大小：`714,692,329` bytes，MD5 `2a9be5c69a89c8eee3fdef0c03efae3a`，与 Figshare API 元数据一致
- 总行数：`6,393,373` 条样本，不是早期记录中的约 950 万
- 字段数：实际有 11 个字段，不是早期记录中的 5 个字段
- 字段：`sgRNA_seq`, `off_seq`, `read`, `sgRNA_type`, `label`, `chr`, `Location`, `Direction`, `Length`, `Method`, `id`
- 标签：`observed_positive=39,319`，`unobserved_candidate=6,354,054`，无非二值标签
- `Method` 字段存在，但 `3,282,935` 行为空；`Length` 字段同样有 `3,282,935` 行为空
- `sgRNA_type_unique=282`，`sgRNA_seq_unique=2,991`

标注语义必须保持：`label=1` 表示 `observed_positive`；`label=0` 表示 `unobserved_candidate`，不能解释为实验验证安全。`read` 字段与标签一致性较好：`observed_positive` 中 38,912 行 read>0、407 行 read 缺失；`unobserved_candidate` 中无 read>0。

Tier-aware 训练不能简单假设全量样本都有检测方法。当前策略是：对 `Method` 非空且已确认方法含义的样本可做 Tier 映射；`Method` 为空、`SURRO-seq`、`Extru-seq` 等未纳入 Tier 表的方法先标为 `unknown`，等待外部来源或论文补充材料确认。`sgRNA_type` 不是基因组位置信息，也不是检测方法字段。

额外注意：CSV 中序列长度混有 22/23/24nt，并包含 `-`。旧 R9/C9 模块的 P0 加权平均只使用本地 23nt NPZ 数据，不直接使用该混合 CSV。

### CCLMoff 权重审计结论

已下载 Figshare 文件 `data/cclmoff/CCLMoff_V1.ckpt`，MD5 `80b311715969524a3972ab75928f3969`，与 Figshare API 元数据一致。但该 checkpoint 的 `state_dict` 前缀为 `encoder`/`decoder`，缺少公开 `CCLMoff/my_model.py` 中的 `rna_model`、`dense1`、`dense2` 权重键。因此它**不能直接当作公开 CCLMoff RNA-FM + MLP 推理权重使用**，除非后续确认官方仓库另有匹配的 inference 代码或权重文件。RNA-FM 本体权重已单独验证为满血版，见 `results/audits/rnafm_verification_report.md`。

### 全局 Run 编码（★核心创新点★）

**Run** = 连续错配段。在 sgRNA（20nt）与 DNA 靶标比对时，看**连续有多少个位置错配**。

**4 种 Run 状态（2-bit 编码，位于 9-bit 向量的 b8-b9）**：
| 编码 | 名称 | 含义 |
|:---:|:---|:---|
| `00` | match | 碱基配对成功 |
| `01` | isolated | 孤立错配（左右都是 match） |
| `10` | run2 | 连续 2 个错配 |
| `11` | run3+ | 连续 3 个及以上错配 |

**关键原则：全局编码，不是局部编码**
- ❌ 局部 Run（错误）：只在 seed 区（16-20）算 Run 状态
- ✅ 全局 Run（正确）：**全部 20 个位置**都算 Run 状态，再结合 seed 梯度加权区分重要性

**Seed 梯度加权（在全局 Run 编码之后应用）**
- 方案 A - Hard 加权：positions 1-15 权重=1.0，positions 16-20 权重=2.0
- 方案 B - Soft 加权（推荐 baseline）：`weight(pos) = exp(-distance_to_PAM / tau)`，`tau=4` 或 `5`
- 方案 C - Learnable 加权：20 个位置各有一个可学习参数，初始化用 Soft 曲线

## 三、版本管理铁律（Git 多版本系统）

### 【绝对禁止】
1. **禁止复制文件夹做版本管理**。过去用 `offtarget_fusion_project/baseline0_cclmoff/`、`artifacts/full_k562_conmismatch9/` 等子文件夹保存不同版本的做法必须彻底废弃。
2. **禁止** `git push --force`、`git reset --hard`、`git clean -f`、`git rebase`（除非用户明确要求并确认）。
3. **禁止**在未经用户确认的情况下执行 `git commit`、`git push`。

### 【强制要求】
1. **所有版本通过 Git 分支 + config 文件切换**。同一套代码库，不同 baseline 用不同 YAML config 和不同模型入口文件。
2. **每个 BL 版本完成后必须打 tag**，格式：`BL{n}-{sub}-v{x.y}`，附注消息必须包含关键指标（AUROC、AUPRC、GPU 内存、epoch 等）。
3. **experiments.csv** 必须同步更新，作为人类可读的实验记录。

### Git 工作流程
```bash
# 1. 开发新 BL 版本时创建功能分支
git checkout -b feat/bl5-series

# 2. 开发与测试
# ... 编码、运行、验证 ...

# 3. 合并回 main 并打 tag（完成后必须执行）
git checkout main
git merge feat/bl5-series --no-ff -m "feat: BL5 series fusion implementations"
git tag -a BL5-3-v1.0 -m "BL5-3 Cross-Attn+Gated | AUROC=x.xx | AUPRC=x.xx | GPU=48GB"

# 4. 查看版本历史
git log --oneline --decorate --tags --graph
```
